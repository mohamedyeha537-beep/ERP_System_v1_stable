# دليل إعداد ثلاث طابعات وتوزيع الطلب الواحد

دليل عملي لمطعم + مقهى (مشروبات = مقهى) باستخدام نظام نقطة البيع الحالي.

**إن كنت تريد فقط قيم نموذج «إضافة / تعديل» في صفحة الطابعات:** انتقل مباشرة إلى **[المرحلة د — شاشة الطابعات](#المرحلة-د--شاشة-الطابعات-ماذا-تكتب-في-كل-حقل)** (جدول لكل حقل × 3 طابعات).

---

## 1) ماذا تريد أن يحدث؟

**طلب واحد** من الكاشير، مثلاً:

| الصنف | القسم |
|-------|--------|
| قهوة + عصير | مشروبات |
| برجر مشوي | مشويات |
| سلطة خضراء | سلطات |

عند **إرسال الطلب للمطبخ** (وليس عند طباعة فاتورة الكاشير فقط):

1. تخرج ورقة على **طابعة المشروبات** — القهوة والعصير فقط  
2. تخرج ورقة على **طابعة المشويات** — البرجر فقط  
3. تخرج ورقة على **طابعة السلطات** — السلطة فقط  

**فاتورة الكاشير** (زر «طباعة» في أمر التجهيز) تبقى **ورقة واحدة** بكل البنود والأسعار — هذا طبيعي ومطلوب.

---

## 2) كيف يوزّع النظام الطباعة؟ (منطق البرنامج)

```
طلب #280
    │
    ├─► بند «قهوة»  ──► قسم DRINKS  ──► مهمة طباعة ──► طابعة 192.168.1.103
    ├─► بند «برجر»   ──► قسم GRILL   ──► مهمة طباعة ──► طابعة 192.168.1.101
    └─► بند «سلطة»   ──► قسم SALAD   ──► مهمة طباعة ──► طابعة 192.168.1.102
```

| الخطوة | أين | ماذا يحدث |
|--------|-----|-----------|
| 1 | الكاشير | يضيف البنود ويضغط **إرسال للمطبخ** |
| 2 | السيرفر | يقسّم البنود حسب **قسم المطبخ** لكل صنف/فئة |
| 3 | السيرفر | ينشئ **تذكرة مطبخ** لكل قسم فيه بنود |
| 4 | السيرفر | ينشئ **مهمة طباعة** (`print_jobs`) لكل تذكرة |
| 5 | الوكيل | يسحب المهام ويرسلها لـ IP الطابعة المناسبة |

**من يحدد القسم؟**

- إعداد **فئة الصنف** في `/catalog/categories` (أو الصنف نفسه)  
- أو **تلقائياً** من اسم الفئة (قهوة → مشروبات، برجر → مشويات، …)  
- أي **صنف جديد** يتبع نفس القواعد إذا وُضع في فئة مناسبة

## 3) لماذا وكيل واحد ورمز (Token) واحد؟

| سؤال | الجواب |
|------|--------|
| هل أحتاج وكيلاً لكل طابعة؟ | **لا** |
| هل أحتاج token لكل طابعة؟ | **لا** |

**وكيل واحد** = برنامج `print_agent.py` على **كمبيوتر واحد** داخل المطعم (غالباً كمبيوتر الكاشير).

**رمز واحد** (`agent_token`) = كلمة سر يثق بها السيرفر لهذا البرنامج.

الوكيل يطبّع على **عدة طابعات** حسب المفتاح في `config.json`:

```json
"printers": {
  "drinks": { "host": "192.168.1.103", "port": 9100 },
  "grill":  { "host": "192.168.1.101", "port": 9100 },
  "salad":  { "host": "192.168.1.102", "port": 9100 }
}
```

الربط بين **قسم المطبخ** و**مفتاح الطابعة** يتم في لوحة الإدارة (`local_printer_key`).

## 4) خطة عناوين IP (مثال — عدّلها لشبكتك)

| الجهاز | IP مقترح | المنفذ | ملاحظة |
|--------|-----------|--------|--------|
| كمبيوتر الكاشير | `192.168.1.10` | — | ثابت، نفس شبكة الراوتر |
| طابعة كاشير (فاتورة) | `192.168.1.100` | 9100 | اختياري إن استخدمت طباعة مباشرة |
| **طابعة مشويات** | `192.168.1.101` | 9100 | |
| **طابعة سلطات** | `192.168.1.102` | 9100 | |
| **طابعة مشروبات** | `192.168.1.103` | 9100 | |

**قاعدة ذهبية:** كل طابعة **IP مختلف**. لا تضع طابعتين على `192.168.1.100`.

**اختبار قبل البدء (PowerShell):**

```powershell
ping 192.168.1.101
ping 192.168.1.102
ping 192.168.1.103
Test-NetConnection 192.168.1.101 -Port 9100
```

### المرحلة أ — الشبكة والطابعات الفيزيائية

3. ثبّت تعريف Windows إن أردت طباعة يدوية — **الطباعة التلقائية من POS لا تعتمد على تعريف Windows**.

### المرحلة د — شاشة «الطابعات»: ماذا تكتب في كل حقل؟

**الرابط:** `http://127.0.0.1:8030/admin/printing/printers`  
(غيّر `8030` إلى منفذ سيرفرك)

**الترتيب:** املأ النموذج من **أعلى لأسفل** كما في الشاشة، ثم **حفظ**، ثم **اختبار طباعة** من الجدول أسفل الصفحة.  
**كرّر العملية 3 مرات** (طابعة مشويات، ثم سلطات، ثم مشروبات).

#### قبل البدء (مهم جداً)

| خطأ شائع | الصحيح |
|----------|--------|
| ترك **الوكيل المحلي** على `—` | اختر من القائمة اسم الوكيل الذي أنشأته (مثل `وكيل مطعم روف`) |
| ترك **الاسم** فارغاً | اكتب اسماً عربياً واضحاً (مثال: `طابعة مشويات`) |
| نفس IP لطابعتين | كل طابعة لها IP **مختلف** على الراوتر |
| `local_printer_key` بحروف كبيرة `GRILL` | استخدم **أحرف صغيرة** فقط: `grill` و `salad` و `drinks` |

**عناوين IP في الأمثلة أدناه:** عدّلها لتطابق طابعاتك الحقيقية (من ملصق الطابعة أو إعدادات الشبكة).  
إن كانت طابعة المشويات عندك `192.168.1.50` كما في صورتك — ضع `.50` للمشويات و`.51` و`.52` للأخريين (لا تكرر نفس الرقم).

---

#### الطابعة 1 — مشويات (GRILL)

املأ الحقول **بالترتيب** ثم اضغط **حفظ**:

| # | اسم الحقل في الشاشة (كما يظهر) | ضع هذه القيمة |
|---|----------------------------------|----------------|
| 1 | **الاسم** | `طابعة مشويات` |
| 2 | **الرمز (فريد)** | `GRILL` |
| 3 | **نوع الاتصال** | `local_agent` |
| 4 | **الوكيل المحلي** | اختر الوكيل الذي أنشأته (مثال: `وكيل مطعم روف`) — **لا تتركه `—`** |
| 5 | **مفتاح الطابعة عند الوكيل (local_printer_key)** | `grill` |
| 6 | **IP (اختياري — للوكيل)** | `192.168.1.101` ← أو IP طابعتك الفعلي (مثال: `192.168.1.50`) |
| 7 | **المنفذ** | `9100` |
| 8 | **عرض الورق (مم)** | `80` |
| 9 | **نشطة** | ✓ مفعّل (مؤشّر) |

بعد الحفظ: من الجدول أسفل الصفحة → **اختبار طباعة** لهذه الطابعة.

---

#### الطابعة 2 — سلطات (SALAD)

امسح النموذج أو أضف طابعة جديدة، ثم املأ:

| # | اسم الحقل في الشاشة | ضع هذه القيمة |
|---|---------------------|----------------|
| 1 | **الاسم** | `طابعة سلطات` |
| 2 | **الرمز (فريد)** | `SALAD` |
| 3 | **نوع الاتصال** | `local_agent` |
| 4 | **الوكيل المحلي** | نفس الوكيل (مثال: `وكيل مطعم روف`) |
| 5 | **مفتاح الطابعة عند الوكيل** | `salad` |
| 6 | **IP** | `192.168.1.102` ← IP طابعة السلطات (مختلف عن المشويات) |
| 7 | **المنفذ** | `9100` |
| 8 | **عرض الورق (مم)** | `80` |
| 9 | **نشطة** | ✓ مفعّل |

→ **حفظ** → **اختبار طباعة**.

#### جدول مرجع سريع (الثلاث طابعات)

| الطابعة | الاسم | الرمز | نوع الاتصال | الوكيل | local_printer_key | IP (مثال) | المنفذ | عرض الورق | نشطة |
|---------|-------|-------|-------------|--------|-------------------|-----------|--------|-----------|------|
| مشويات | طابعة مشويات | `GRILL` | `local_agent` | وكيلك | `grill` | `.101` أو `.50` | `9100` | `80` | ✓ |

### المرحلة و — ربط الفئات والأصناف

اذهب إلى: `/catalog/categories`

- فئات المشروبات/القهوة/العصائر → قسم **مشروبات**
- فئات اللحوم/البرجر/المشويات → قسم **مشويات**

## 6) التشغيل اليومي (للكاشير)

1. تشغيل السيرفر: `python run.py` أو `restart-server.bat`
2. تشغيل الوكيل: `python print_agent.py`
3. من POS: إضافة البنود → **إرسال للمطبخ**
4. كل قسم يطبع ورقته تلقائياً خلال ثوانٍ
5. للفاتورة: فتح أمر التجهيز → **طباعة** (صورة مطابقة للمعاينة)

## 7) مراقبة المشاكل

| المشكلة | الحل |
|---------|------|
| لا تطبع أي قسم | هل الوكيل يعمل؟ هل `server_url` صحيح؟ |
| قسم واحد فقط لا يطبع | راجع `local_printer_key` = مفتاح `config.json` |
| مهمة `failed` | `ping` + منفذ 9100؛ كابل الشبكة |
| بند لا يذهب للقسم الصحيح | راجع فئة الصنف في `/catalog/categories` |
| طباعة كاشير لا تعمل | `/admin/settings` + طابعة كاشير + Pillow للوكيل |

**مركز المراقبة:** `/admin/printing/jobs`  
**شاشة المطبخ:** `/admin/kds`

## 10) ملخص في جملة

**وكيل واحد + token واحد** على كمبيوتر المطعم، و**ثلاث مفاتيح طابعات** في `config.json`، و**ثلاثة أقسام مطبخ** مربوطة بفئات الأصناف — عند إرسال طلب واحد للمطبخ يقسّم النظام البنود ويطبع **ورقة منفصلة لكل قسم** على طابعته.
